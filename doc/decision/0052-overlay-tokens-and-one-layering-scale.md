# 0052 – Overlay tokens and one layering scale

## What

A new token module, `libs/shared/design-system/tokens/src/lib/overlays.ts`, and the
section generated from it in `tokens.css`:

| token | value | origin |
| --- | --- | --- |
| `--z-sticky` | `40` | FROM THE DESIGN (sticky header) |
| `--z-bar` | `50` | FROM THE DESIGN (fixed bottom bar) |
| `--z-overlay` | `60` | FROM THE DESIGN (modal scrim) |
| `--z-dropdown` | `70` | INVENTED |
| `--z-toast` | `80` | INVENTED |
| `--z-tooltip` | `90` | INVENTED |
| `--scrim` | `rgba(10,10,10,0.6)` | FROM THE DESIGN, verbatim (3×) |
| `--modal-w-sm` | `460px` | FROM THE DESIGN (`width:min(460px,100%)`) |
| `--modal-w-md` | `620px` | FROM THE DESIGN (bulk action) |
| `--menu-min-w` | `246px` | FROM THE DESIGN (avatar menu `width:246px`) |
| `--tab-indicator-h` | `3px` | FROM THE DESIGN (`border-bottom:3px solid`) |
| `--tooltip-max-w` | `240px` | INVENTED (the design has no tooltip) |
| `--toast-w` | `380px` | INVENTED (the design has no toast) |

Only **`--scrim`** is mapped into the Tailwind bridge (`theme.css`), as
`--color-scrim` — it is a color, so it earns the `bg-scrim` utility. The rest is
consumed as an arbitrary value.

## Why

- **Overlay components have nothing to reach for.** `colors_and_type.css`
  describes a flat page – it knows nothing about layer order, a dimmed
  background, or a dialog's width. Without tokens the primitives would end up
  holding inline values (`z-[60]`, `bg-[rgba(10,10,10,0.6)]`, `max-w-[460px]`),
  which violates global constraint 5.
- **Layering has to be one scale.** If every component picked its own
  `z-index`, two of them would sooner or later agree and the order would start
  depending on DOM order. The three values from the design (40/50/60) anchor the
  scale; the three above them are invented, but their **order** is the part that
  matters:
  - a menu opens from its trigger and has to beat the bars around it,
  - a toast has to beat a menu, because it can arrive while a menu is open,
  - a tooltip sits at the very top, because it can describe anything above –
    including a toast's close button.

  Gaps of ten leave room to slot a layer in without renumbering.
- **`--scrim` cannot be assembled from the neutrals.** It is a translucent
  black, whereas every `--neutral-*` is opaque.
- **`--tab-indicator-h` has to be a token.** 3px is not on the `--space-*` scale
  (which starts at 4px) and it is not one of Tailwind's `border-b-*` steps
  (1/2/4/8).

## How

- Every entry in `overlays.ts` states whether it is FROM THE DESIGN or INVENTED
  – the same convention as `controls.ts`
  (`doc/decision/0011-derived-control-tokens-and-rounding.md`) and `layout.ts`
  (`doc/decision/0011-breakpoints-are-derived.md`).
- The `generate-css.ts` generator gains an `Overlays and layering` section, so
  the drift test in `generate-css.spec.ts` covers the new tokens too.
- In `theme.css`, the unmapped tokens carry a comment saying why they are not
  mapped: Tailwind v4 has neither a `--z-index-*` nor a `--border-width-*`
  namespace. Consumption:

  ```
  z-[var(--z-overlay)]
  max-w-[var(--modal-w-sm)]
  min-w-[var(--menu-min-w)]
  border-b-[length:var(--tab-indicator-h)]
  ```

  The `length:` hint on the last one is **mandatory**: `border-b-[var(--x)]` is
  ambiguous to Tailwind and would be read as a border color. Verified against
  the CSS generated by the Storybook build – it emits
  `border-bottom-width:var(--tab-indicator-h)`.

### Rounding against the design

| place in the design | design | used | difference |
| --- | --- | --- | --- |
| modal padding | 28px | `p-6` (24px) | −4px |
| menu item padding | 10px 12px | `px-3 py-3` (12px) | +2px vertically |
| gap between menu items | 2px | `gap-1` (4px) | +2px |
| modal radius | 24px | `rounded-lg` | 0 |
| modal and menu shadow | `0 20px 48px rgba(35,34,31,0.12)` | `shadow-lg` | 0 |
| menu radius | 16px | `rounded-md` | 0 |
| menu item radius | 12px | `rounded-sm` | 0 |

Same principle as in
`doc/decision/0011-derived-control-tokens-and-rounding.md`: a step off the
scale is preferable to a new token for every individual value. No deviation is
larger than 4px.

## Risk

- **The invented values only get checked at visual review.**
  `--tooltip-max-w`, `--toast-w` and the top three `z` layers have no model in
  the design. Each of them is a one-line change in `overlays.ts` plus a CSS
  regeneration.
- **The dropdown's `z-index` is local.** Dropdown is not a portal, so its
  `z-[var(--z-dropdown)]` applies inside the trigger's stacking context. Inside
  a sticky header (`z-index:40`) the menu therefore **does not** beat a modal at
  60, even though it carries 70 – which is correct, but surprising if someone
  reads the values as global.
- **Modal is a portal, Dropdown is not.** If someone converted Dropdown to a
  portal, the values would start applying globally and the behaviour would
  change. That is why it is written in both components' docstrings.
